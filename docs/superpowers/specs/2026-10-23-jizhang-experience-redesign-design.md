# 记账本体验重构设计规格

## 目标

在不改变现有本地优先数据层、云同步和账务计算口径的前提下，重建小程序的视觉系统与高频交互，让首页、记一笔、统计、我的四个核心入口具备一致、成熟、可预测的使用体验。

## 2026-10-24 视觉修订

根据实际使用反馈，全局视觉统一为暖黄色账本主题：纸白背景、奶油黄卡片底、琥珀金主操作、深棕文字和深金色数据。收入、超支、删除等状态色只在需要表达语义时保留，页面主色、导航、会员页和统计图表均使用同一套黄色令牌。

## 用户与产品判断

产品服务的是需要快速记录日常收支、偶尔回看趋势并管理家庭账本的人。最重要的任务顺序是：快速记一笔、理解当前月度状态、找到异常或下一步行动、管理账户和账本。通过纸白、暖黄和深棕的明暗层级表达金额、状态和行动。

## 视觉系统

- 背景：`#FFF9EE` 纸白，页面底色保持轻盈。
- 墨色：`#3B2A18` 深棕，用于标题、数字和导航。
- 次级文字：`#7A6A53`，辅助文字使用 `#9A896D`。
- 主行动：`#F6C95B` / `#E8A72D` 暖黄与琥珀金，适用于记一笔、预算进度和选中态。
- 柔和表面：`#FFF0C2` 奶油黄，用于芯片、提示和次级操作。
- 语义状态：收入使用深金色，风险和删除保留赤陶红，只用于表达状态。
- 卡片：`#FFFFFF`，边框使用 `#EFE3C7`，阴影使用暖棕低透明度阴影。

字体继续使用系统中文字体，数字使用等宽数字特性。统一圆角、间距和控件触控尺寸，公共样式集中在 `app.wxss`。

## 核心页面

### 首页

顶部显示账本切换和同步状态；主卡以“本月结余”为视觉焦点，同时保留收入、支出和预算进度。底部固定 tab 中间的 `记一笔` 作为全局主行动，首页次级入口集中到可滚动的快捷功能区。账单按天分组，支持成员筛选、列表/日历切换、月份左右滑动、下拉刷新和清晰空状态。

### 记一笔

金额、类型、分类三者形成单一主流程。数字键盘和完成按钮固定在可视区域底部；最近使用分类优先展示；账户、备注、日期等低频信息收进“更多信息”区域。保存后使用短时成功反馈，并提供返回首页的稳定路径。

### 统计

页面首屏先给出本期总额、环比和最大分类三个洞察，再展示趋势、占比、近 12 个月柱状图。周期和收支切换使用统一分段控件；没有数据时给出明确的下一步入口，而不是只显示空白图表。

### 我的

顶部统一展示头像、昵称、同步状态和账本入口；资产概览作为第一张内容卡；预算、挑战、账本、分类、导入导出和帮助等功能按任务分组，统一列表行、状态标签和箭头反馈。

## 交互规范

- 所有可点击区域至少约 `88rpx` 高或等效触控面积。
- 统一使用按压态、底部弹层、确认弹层、成功/失败 toast 和加载占位。
- 关键数据更新后即时刷新相关卡片与列表，不依赖重新进入页面。
- 允许减少动效系统设置；动效只用于层级进入、成功反馈和主操作确认。
- 错误信息写明发生了什么以及用户下一步能做什么。
- 四个核心页面按微信胶囊底边预留顶部安全间距，兼容缺失胶囊信息的环境。
- 页面弹层打开时隐藏自定义底部导航，关闭后恢复，保证弹层操作可见且可点击。
- 底部导航采用普通 view 与同层 2D canvas 配合；透明区域允许页面接收点击，按钮单独接收点击，并按底部安全区上移。
- 统计刻度以分为基础计算，金额按元或万元显示；空趋势显示记账入口。取消日期选择保留原统计周期。

## 范围与约束

- 修改公共视觉令牌、公共卡片/按钮/列表/弹层样式、自定义 tabbar。
- 重做 `pages/index`、`pages/edit`、`pages/stats`、`pages/profile` 的 WXML/WXSS，必要时补充 JS 状态反馈。
- 其余页面优先通过公共令牌和通用类迁移，保持业务逻辑与接口不变。
- 不新增第三方依赖，不改动 `utils/db.js`、`utils/cloud.js` 的数据协议。
- 完成后运行现有 Node 测试，并检查 WXML/WXSS 结构和关键交互引用。

## 验收标准

1. 四个核心页面使用同一套颜色、圆角、间距、按钮和弹层规则。
2. 首页、记一笔、统计、我的的主要操作路径不需要新增步骤，且有明确成功/失败反馈。
3. 收入、支出、结余、超支、同步状态在颜色和文案上有一致含义。
4. 现有测试全部通过，页面文件无引用不存在的事件处理函数。
