# 外部账单导入去重

本轮补齐已有导入流程的去重与预览，不自动清理用户历史账单，不向真实账本写入测试数据。

- 微信、支付宝交易单号优先；单号中的空白与占位符会清洗。单号使用字符串，避免长数字精度损失。
- 无单号使用来源、交易日期与时间、收支方向、金额、交易对方、商品说明和支付方式组成稳定身份。解析与入账共用规则，原始快照保存后不受用户编辑备注、金额或日期影响。
- 去重以目标账本为边界，包含该账本回收站中的流水；文件内重复与此前已导入流水均跳过。金额相同的手记账单不会自动当作重复项。
- 导入前仅展示新增明细及其金额汇总，提示排除的重复数。全部重复时禁用导入；提交时再次检查，防止预览期间同步到来的记录再次入账。
- 单次免费额度在去重后计算，未导入的新增记录保留，可继续导入。
- 旧版无单号记录按当时保留的日期、方向、金额、对方与备注兼容匹配；旧全局冗余键优先按已有记录归属迁移，无法还原归属的孤立键归升级时当前账本。
- 旧版本机仍保留的导入标识通过独立身份补传同步，不提升财务版本，不覆盖远端金额或删除状态。服务端以 external_at 将身份补齐传播到增量设备，客户端允许同财务版本补齐缺失身份。

## 发布依赖与边界

服务端新增 records.external_json 与 external_at，两列启动时自动迁移。server.js 仍可独立部署。跨设备身份保留与旧身份补传需要更新服务端；本次只修改本地源码，尚未部署线上。

若历史导入来源已在所有设备中丢失，则无法可靠还原交易单号；不会仅凭日期和金额自动删除或吞掉历史记录。无单号且所有可见交易字段完全一致时，无法区分两笔实际交易与同一流水副本。两个离线设备在互相同步前同时导入的并发冲突，当前仍由账单同步机制处理，不声称有服务端交易唯一约束。

## 验证

新增去重专项 10 项行为测试；账单解析测试 16 项；服务端 19 项，包括真实 HTTP 往返、新设备重复导入、旧客户端编辑保留身份、旧身份补传不覆盖新财务状态及增量传播。已执行 npm test、npm run test:ui、npm run test:compile。仅使用内存存储及临时测试数据库，未导入真实账本。
