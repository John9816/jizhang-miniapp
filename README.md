# 记账本 · 日常收支记账小程序

一个微信原生小程序：记录每天的收入和开销，支持多人共享账本，并按成员展示记账来源与汇总。

## 功能清单

**1. 收支记录管理**
- 添加 / 编辑 / 删除记录，每条包含：金额（精确到分）、日期、分类、备注、收支类型、账户
- 首页按月份查看（‹ › 切换），记录按日期分组，组内显示当日收/支小计
- 汇总卡片：本月总收入、总支出、结余
- **日历视图**：月份栏右侧 📅 切换，月历展示每日收支标记，点某日看当日明细

**2. 统计图表（对标随手记/挖财的分析内核）**
- 统计页：周 / 月 / 年 / 自定义周期切换，含环比
- 分类占比环形图 + 图例（支出/收入可切换）、分类排行（金额/占比/笔数）
- 收支趋势折线图（按日/周）、近 12 个月支出柱状图
- **年度账单海报**：生成渐变海报，长按保存 / 微信分享

**3. 预算管理**
- 月度总预算 + 分类预算（如餐饮每月 1000）
- 执行进度条、执行率、超支红字；支出达 80% 或超支时首页横幅提醒

**4. 搜索与导出**
- 组合搜索：关键词（备注/分类/记录人）、类型、成员、分类、日期区间、金额区间
- 快捷选择本月、近三个月、今年；日期与金额区间校验，编辑返回后保留条件并刷新结果
- 结果按日分组 + 汇总；账本和对账页支持**导出 CSV 文件**或复制内容（带 BOM，保留自定义分类与多行备注）

**5. 资产账户**
- 现金 / 储蓄卡 / 信用卡 / 支付宝 / 微信钱包等账户，记录时可关联
- 资产页：净资产汇总、各账户余额、账户流水；信用卡填负数初始余额即为负债
- **转账**：账户间互转（不计入收支统计，不影响结余）

**6. 自定义分类**
- 账本级自定义支出/收入分类：增删、改名、图标选择、停用、排序
- 共享账本内成员同步使用；停用不影响历史记录

**7. 周期记账**
- 工资、房租等固定收支按周/月/季/年自动入账
- 到期在首页打开时自动执行（幂等，多设备不重复）；支持暂停、立即记一笔

**8. 共享账本（邀请指定的人共同记录）**
两种模式，`config.js` 一键切换：

- **本地模式（默认，零服务器）**：账本页 →「复制分享包」→ 微信发给好友 →「加入账本」→ 粘贴导入；按记录 ID 去重合并。各自新记的条目先存本机，再次互发分享包即可同步
- **云端模式（自部署后端）**：账本页 →「复制邀请码」→ 好友「输入邀请码」加入，之后**双方记录实时同步**，换设备重新登录即可恢复全部账目。部署步骤见 [DEPLOY.md](server/DEPLOY.md)

**9. 成员区分与汇总**
- 每条记录带有记录人昵称标签（成员页可修改，改名后历史记录同步更新）
- 首页可按成员筛选记录
- 成员页展示各成员累计记录数、收入、支出

## 如何预览

1. 打开「微信开发者工具」→ 导入项目 → 选择本目录（`jizhang-miniapp`）
2. AppID 选择「测试号 / 游客模式」即可编译预览（工程已内置 `touristappid`）
3. 首次进入会提示设置昵称（用于共享账本时标注记录来源），之后自动创建「我的账本」

## 本地测试（微信开发者工具 + 本机后端，零微信账号）

一条完全在本机跑的测试链路：开发者工具模拟器 → 本机 MOCK 后端 → SQLite 文件，**不需要真实 AppID、不需要服务器**。

```
微信开发者工具(模拟器)  ──http://127.0.0.1:3123──▶  本机后端(MOCK_WX=1) ──▶ jizhang-data/jizhang.db
tests/local-second-device.js ──┘  （模拟"另一个人的手机"）
```

**第 1 步：起本机后端**（项目已内置 `config.local.js` 指向它）

```bash
cd server
MOCK_WX=1 PORT=3123 HOST=127.0.0.1 \
  DATA_DIR=../jizhang-data node server.js
```

**第 2 步：开发者工具导入**

1. 微信开发者工具 → 导入项目 → 选择 `jizhang-miniapp` 目录，AppID 用「测试号 / 游客模式」
2. **详情 → 本地设置 → 勾选「不校验合法域名」**（连 `http://127.0.0.1:3123` 必须，模拟器里才允许 HTTP + 本机地址）
3. 编译。`config.local.js` 已把 `cloud.enabled=true`、`apiBase=http://127.0.0.1:3123`，登录走 MOCK（任意 code 映射 mock 身份）

**第 3 步：按清单测功能**

| 测什么 | 怎么做 | 预期 |
| --- | --- | --- |
| 记账全流程 | 首页「记一笔」→ 编辑 → 删除 → 切月份 | 列表/小计/月汇总即时正确 |
| 数据真的上了后端 | `node tests/dump-db.js` | 能看到 users/ledgers/records 表内容 |
| 同步状态 | 首页顶部状态行 | 「已同步 HH:MM」而非「待连接」 |
| 邀请码共享 | 账本页复制邀请码 → 跑下面的命令 → 回首页下拉刷新 | 出现「测试好友」记的一条记录 |
| 离线补同步 | `Ctrl+C` 停掉后端 → 记几笔 → 重启后端 | 恢复后自动推送，不丢 |
| 全自动回归 | `node tests/local-e2e.js` | 14 项全过（双设备同步/墓碑/越权/鉴权） |

**模拟第二台设备**（好友那一侧）：

```bash
node tests/local-second-device.js <邀请码>                    # 加入账本+回记一笔
node tests/local-second-device.js <邀请码> --also 交通 25 打车  # 自定义这笔
node tests/local-second-device.js --dump                       # 只看服务端数据
```

**切回线上 / 真机测试**：删掉 `config.local.js`、去掉「不校验合法域名」勾选，`config.js` 本身保持线上配置（`jizhang-api.751152.xyz`）即可。注意**真机预览无法访问你 Mac 的 127.0.0.1**，真机测试须用线上后端（request 合法域名配好后预览扫码）。

## 运行测试

```bash
npm test                      # 核心功能、同步生命周期、账务可靠性、文件导出、后端
npm run test:ui               # 页面行为、搜索筛选、编辑保护与样式结构回归
npm run test:compile          # 使用微信开发者工具自带 wcc/wcsc 验证全部模板与样式
node tests/util.test.js         # 数据层 / 纯函数（12 用例）
node tests/stats.test.js        # 统计/预算/账户/周期/CSV 纯函数（11 用例）
node tests/cloud.test.js        # 云端适配层（9 用例）
node tests/ledger-extras.test.js # 账本级新模型（11 用例）
node tests/server.test.js       # 后端端到端（13 用例，含老库自动迁移）
node tests/local-e2e.js         # 本机双设备全链路（14 用例，需先起本机后端）
```

默认测试不读写真实账务数据。`local-e2e.js` 需要单独启动隔离的本机后端；调试时可用 `JZ_DEBUG=1` 查看同步请求。

`test:compile` 默认使用 macOS 已安装的微信开发者工具；其他安装位置可用 `WECHAT_COMPILER_DIR` 指向包含 `wcc` 和 `wcsc` 的目录。界面动效遵循系统“减少动态效果”，主要弹层保留退出阶段遮罩，避免点击穿透。

## 数据与后续升级

- **本地模式**：数据经 `wx.setStorageSync` 存在本机，入口统一在 `utils/db.js`
- **云端模式**：本机存储仍是页面唯一数据源（离线优先），`utils/cloud.js` 负责登录、推送脏数据、拉取增量按 LWW 合并；断网可用，恢复网络自动补同步
- 页面只依赖 `db.js` 暴露的接口，切换云端模式**不需要改任何页面代码**
